## Entry 1

### Alert

SIEM Rule Triggered — Mass File Access by Privileged Account

Severity: High | Source: Windows Event Logs / File Access Logs

Account: svc-backup@company.com (service account)

Activity: 14,000+ file read operations on Finance shared drive

Timeframe: 02:06–03:41 (Sunday)

Source host: BKPSRV-01

Change management: Approved change request for backup scope expansion submitted 3 days prior (CHG-2291)

EDR status: No malicious activity detected

Baseline: Same account accessed same share weekly at similar times for past 6 months

### Signals

- 14,000+ file read operations on Finance shared drive by svc-backup@company.com detected at 02:06–03:41 on Sunday.
- Approved change request for backup scope expansion submitted 3 days prior (CHG-2291).
- Same account accessed same share weekly at similar times for past 6 months.

### Alternative Hypothesis

- svc-backup credentials might have been compromised; the attacker might be using the routine as a mask to exfiltrate data to C2.

### Decision

- Close.

### Justification

- The correlation of clean EDR status, 6 months of same operation baseline, and CHG-2291 approval indicates that this operation is a benign backup operation.

### Rejection Reasoning

- All 3 signals: same account accessing same share weekly at similar times for 6 months, clean EDR status and most importantly the approved CHG-2291 request indicate that this process is most likely done by an authorized person, a benign operation.

### Escalation Condition

- If any unexpected volume spikes, unauthorized access from unrecognized host, account, or a different timeframe from baseline; or C2 connection for data exfiltration are observed after this alert, the incident transitions from benign to escalation.

## Entry 2

### Alert

SIEM Rule Triggered — Single Beacon to Low-Reputation External IP

Severity: Medium | Source: Firewall Logs / NetFlow

Endpoint: WKSTN-071 (Customer Support)

Outbound connection count: 1 HTTPS session

Destination IP: 103.77.201.19

Threat intelligence: Low reputation score, no confirmed malware association

Connection duration: 14 seconds

No follow-up connections, process executions, or persistence activity observed

EDR status: Clean

30-day baseline: No previous communication with this IP

### Signals

- Single beacon to external IP detected via 14-second HTTPS connection.
- No prior communication with this IP observed in 30-day baseline. IP carries a low reputation score in threat intelligence with no confirmed malware association.
- No follow-up connections, process executions, or persistence activity observed. EDR status is clean.

### Alternative Hypothesis

- Installed software on the endpoint such as CRM or helpdesk tools may have connected to an external IP for update checks, license verification, telemetry, or cloud sync. The absence in the 30-day baseline may be explained by a recent software installation.

### Decision

- Monitor.

### Justification

- A single beacon is not sufficient for escalation, but the unknown source of the triggering process raises suspicion. Monitoring is required to observe post-beacon activity.

### Rejection Reasoning

- The originating process has not been identified, preventing confirmation that the connection was generated by a legitimate application.

### Escalation Condition

- If the external IP is confirmed C2, the beacon is confirmed as a malicious script, or repeating connections to the same IP are observed, the incident's scope expands to C2 communication. The decision changes to escalate + contain.

Endpoint: WKSTN-047 (HR Department)

Domains registered: 72 hours prior | First observed in environment

Prior endpoint activity: No suspicious events in preceding 7 days

EDR status: No alerts generated

### Signals

- DNS queries occurred to 3 separate, newly registered, never-seen-before domains in 4 minutes from one endpoint.

### Alternative Hypothesis

- Browser prefetch, software update or any system background activity might have triggered these DNS queries without user action.

- Monitor.

### Alert

SIEM Rule Triggered — Scheduled Task Created by Office Child Process

Severity: High | Source: Windows Event Logs / EDR

Endpoint: WKSTN-155 (Operations Dept.)

Process chain: winword.exe → cmd.exe → schtasks.exe

Scheduled task created: "AdobeUpdaterCheck"

Execution trigger: Daily recurring task

Attachment history: User opened external .docx attachment from email 4 minutes prior

EDR status: No malware signature detected

Baseline: No prior scheduled task creation activity from Office applications on this endpoint

### Signals

- winword.exe -> cmd.exe -> schtasks.exe process chain detected. Daily recurring scheduled task created.
- User opened external .docx email attachment 4 minutes prior. High probability phishing.
- No prior scheduled task creation from Office applications on this endpoint in baseline.

### Alternative Hypothesis

- IT department sent a macro-enabled Word document to deliver update checker scripts.

### Decision

- Escalate + contain.

### Justification

- All 3 signals point to the start of a persistence execution. User opening attachment document, winword.exe spawning cmd.exe then a scheduled task being created as AdobeUpdaterCheck, with baseline confirming no prior scheduled task creation from Office apps. Signal correlation requires escalation + immediate containment since scheduled task is already created and may execute before containment.

### Rejection Reasoning

- Email attachment is not a legitimate IT script delivery channel. The AdobeUpdaterCheck task name has no related Adobe context on this endpoint, consistent with masquerading technique.

### Escalation Condition

- If scheduled task is detected running actively, persistence is confirmed. Credential exposure, lateral movement, exfiltration risk opens.
- If payload analysis reveals C2 beacon or equivalent, the scope expands beyond single endpoint, network-wide IR response triggered.
